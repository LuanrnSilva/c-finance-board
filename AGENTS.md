- Card used amount is computed from expense transactions (credit_card_id, current month); credit_cards.used_amount is deprecated — keeps a single source of truth.
- Parse "YYYY-MM-DD" dates with parseLocalDate from src/lib/utils — new Date(str) shifts the month in UTC-3.
- Installment purchases are stored as one row per installment linked by installment_group_id — enables per-month totals and group deletion.
- The Transaction type lives only in src/types/transaction.ts.
- Shared data (transactions, credit_cards, categories, contracts, people) is scoped by household_id with RLS via public.is_household_member; user_id means "created by" — lets household members share everything.
- Get the current household with getHouseholdId() from src/lib/household (calls ensure_household RPC); one household per user — keeps inserts valid even after a member is removed.
- Expense validation status (pending/confirmed/disputed) is enforced by DB triggers on transactions; totals use countsTowardTotals from src/types/transaction (disputed excluded) — creators cannot validate their own entries.
- Goals use TanStack Query (useGoals); progress/monthly-needed math lives in src/lib/goals — one place for the formula.
- Recurring-expense detection is client-side in src/lib/recurring (detectRecurring); user confirm/ignore choices persist in recurring_overrides keyed by normalized description + category.
- Report/budget calculations (budget levels, member spend, cumulative balance, top expenses, month projection) live in src/lib/reports and exclude disputed entries via countsTowardTotals.
